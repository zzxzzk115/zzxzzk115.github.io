# Kexuan Zhang's homepage

Personal content and deployment configuration for [zzxzzk115.github.io](https://zzxzzk115.github.io/).

- Academic: `/`
- Casual: `/casual/`
- Independent VuePress blog: `/blog/`

The Astro + Vue presentation lives in the separate `academic-casual-template` repository. `template.lock.json` pins the exact template commit used by CI. Personal content updates do not require copying or editing template components.

## Edit content

Update `site.config.yaml` for identity, contact, navigation, featured projects, colors, or integrations. Use `content/` for Markdown projects/posts/news, biography, profile, CV, repositories, BibTeX, and the blog feed snapshot. Put images and documents in `public/`; these retain their public paths. The default contact is **sc23kz@leeds.ac.uk**.

The longer biography, 7 project pages, 2 homepage posts, news item, publication, and CV have been migrated from the previous Jekyll site. Existing underscores in project slugs, article URLs, heading anchors, Giscus pathname mappings, PDF paths, and the root feed are retained. The original CV PDF keeps its existing Gmail contact; there is no staff address in it.

The homepage fetches the English JSON Feed at build time and uses `content/blog-feed.json` when it is unavailable. Rebuilding the homepage refreshes its article summaries. The blog's articles, Chinese locale, comments, repository, and deployment remain independent.

## Local development

Clone the template into a sibling directory, check out the revision in `template.lock.json`, and run:

```sh
cd ../academic-casual-template
pnpm install --frozen-lockfile
pnpm site dev --content ../zzxzzk115.github.io
pnpm site build --content ../zzxzzk115.github.io --out ../zzxzzk115.github.io/dist
pnpm site preview --content ../zzxzzk115.github.io --out ../zzxzzk115.github.io/dist
node scripts/verify.mjs ../zzxzzk115.github.io/dist ../zzxzzk115.github.io
```

Node 24 and pnpm 10.34.5 are used in CI. Production builds generate the local search index; search is not generated by the dev server.

## Publish and rollback

Pull requests build and verify the homepage and upload a preview artifact. The main branch publishes the verified output to the existing `gh-pages` branch. The root build does not produce a `/blog/` directory, so the separately hosted project site remains independent.

The pre-migration source is preserved by tag `pre-astro-migration` (commit `878a9749b81018c2c45a376911ab4ce6fcc8ea97`). Legacy Jekyll source files are retained as reference but are not read by the Astro build. Legacy build/report workflows are stored inactive under `.github/legacy-workflows/`; CodeQL remains active.

To restore the previous site without rewriting history, use a separate checkout of the tag, run its documented Jekyll build, and deploy that `_site` output to the same `gh-pages` branch. To roll back an Astro version, restore the corresponding content commit and template pin, then rerun the homepage workflow.

The existing MIT license and legacy theme attribution are preserved. The new template is independently MIT licensed.
